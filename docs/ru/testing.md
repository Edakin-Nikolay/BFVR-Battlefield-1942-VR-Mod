# Как тестировать наши наработки в игре

Статус: актуально (метод), подтверждение на гарнитуре — по факту прогонов.

## Базовое правило

Мы не тестируем «на глаз» в игре то, что можно проверить тестом.

1. **Чистая математика** (clamp, матрицы, лучи) — только детерминированные
   тесты + `ctest`. Игра для этого не нужна.
2. **Видимое поведение гарнитуры** (что реально видит пользователь на Quest 3) —
   только живой прогон, и утверждается после подтверждения пользователем.

Отсюда два отдельных контура: быстрый разработочный и релизный.

## Контур 1 — разработочный (без инсталлятора)

Инсталлятор каждый раз собирать **не нужно**. Он нужен для чистовой проверки
установки и релиза, а не для ежедневной итерации.

Рекомендуемый порядок:

1. Собираем Win32 (Ninja, x86 VsDevShell) и x64 presenter.
2. Гоняем `ctest` — математика должна быть зелёной до запуска игры.
3. Разворачиваем binaries в отдельную папку-полигон вне репозитория,
   например `G:\Strata\workspace\BF1942_vr\_test\BFVR`, через
   `tools\Stage-BFVRPlayer.ps1`. Это ровно тот же payload, что берёт
   инсталлятор, поэтому поведение идентично.
4. Для быстрых итераций binaries (не конфиги) делаем жёсткими ссылками на
   свежую сборку (`New-Item -ItemType HardLink`), чтобы не копировать заново:
   пересобрали — полигон уже содержит новый файл.

Наш полигон развёрнут в `test\` (вне репозитория): `test\player` — payload,
`test\tools\Stage-BFVRTestBench.ps1` — его сборка,
`test\tools\Verify-BFVRTestBench.ps1` — проверка, что ссылки не разошлись с
правилами, `test\tools\Run-TestSuite.ps1` — сборка + полный `ctest`,
`test\tools\Run-BFVRBench.ps1` — запуск игры из стенда с явным
`--game-root`. Инструкция — `test\README.md`.

Важные ограничения:

- Жёсткие ссылки работают только в пределах одного тома (G:), поэтому полигон
  держим на G:, а не в папке игры на другом диске. Если источник на другом томе,
  hard link невозможен — скрипт делает копию.
- Symbolic link требует прав администратора или Developer Mode, поэтому стенд
  использует только hard links и junctions: junction работает между томами и
  создаётся без прав.
- ИгруLink — только одним junction на каталог (`test\game -> H:\Games\Battlefield 1942`),
  никогда не копия и не набор файлов в папке игры. Если игра обязана видеть
  файлы в своей папке, делайте junction из папки игры на полигон, а не копию, и
  сначала сохраняйте копию установленной релизной папки (реестр и uninstaller
  указывают на неё).
- `UserConfig.txt` — копия из установленной версии: инсталлятор его
  сохраняет, а полигон без него ведёт себя иначе (first-run).
- В репозиторий ссылки/полигоны не кладём (AGENTS.md: личные тестовые
  установки в репозиторий не добавляются).

Что этот контур **не** доказывает: что установщик, ярлык, OpenXR runtime
manifest и uninstaller работают. Для этого — контур 2.

## Контур 2 — релизный (инсталлятор)

Раз в контрольную точку (перед публикацией и перед проверкой «чистая
установка»):

1. `Stage-BFVRPlayer.ps1` → payload;
2. `ISCC.exe` с `/DPayloadRoot` и `/DOutputRoot` (Inno Setup 6.7.3);
3. прогон checklist: свежая установка, апгрейд с предыдущего публичного
   инсталлятора, repair той же версии, uninstall.

Итог: инсталлятор — для финальной проверки и релиза; ссылки/полигон — для
повседневной работы.

## Проверка на гарнитуре (Quest 3)

Перед прогоном фиксируем в `notes/state.md`:

- что именно ожидаем увидеть (например: head не выходит за объём станции);
- ожидаемое «никакое» поведение (decoupled camera не изменилась);
- цифру из теста, которую сверяем с ощущениями.

Без этого прогон не считается подтверждением, а только впечатлением.

## Экранные снимки и выбор глаза (левша)

Desktop mirror по умолчанию показывает правый глаз. Для левшей и диагностики:

```powershell
$env:BFVR_MIRROR_EYE='left'   # или 'right'
```

Переменная читается presenter'ом при старте; в `BFVRPresenter-game.log`
пишется строка `Desktop mirror eye: left/right`. На рендер в шлеме не влияет.

## Экспериментальный spread (только SP/LAN)

`BFVR_EXPERIMENTAL_SPREAD_SCALE_PERCENT=0..100` (по умолчанию 100 = выключен).
Протокол замера: `test/checklists/2026-11-13-spread-sp.md`, исследование:
