# Расследование дрейфа рук при повороте стика (SP-боты)

## Симптом (видео пользователя, 2026-11-14)

- В SP с ботами, стоя на месте, кисти рук дрейфуют при повороте тела стиком.
- Начало движения (ходьба/бег) сбрасывает дрейф — руки возвращаются на место.
- Уровень сглаживания Off дрейф не устраняет.

## Что уже проверено: аналитический тест якоря

Новый тест `TestControllerWorldPoseStaysFixedAcrossBodyYaw`
(`src/client/D3D8TrackingAnchorTests.cpp`, строки 399–468) проверяет
согласованность якоря трекинга с поворотом VR-представления:

- обе руки, grip и aim, независимо;
- повороты ±720° (обе стороны), 96 кадров по 7.5°;
- движущееся и неподвижное тело (поступательное смещение корня);
- «догоняющее» тело колбэка (callback body отстаёт/нагоняет presentation yaw).

Тест проверяет: позиция и ориентация кисти, пересчитанные через текущий yaw
тела, следуют yaw VR-представления, независимо от отставания тела.
При вращении самого представления кисть не фиксирована в мире. Тест проходит.

## Граница доказательства

Тест доказывает корректность алгебры якоря ТОЛЬКО для смоделированных
трансформаций внутри теста. Он не проверяет фактическое владение (ownership)
позами скелета в рантайме: кто и когда пишет матрицу скелета, каким yaw
реально владеет нативный код. Дрейф в видео — рантайм-эффект; тест его
не воспроизводит и не исключает.

## Гипотезы (без установленной причины)

1. **Нативная анимация/IK**: игра решает позы рук сама; расхождение между
   запрошенными IK-целями и решёнными позами (root/body yaw, лаг корня
   скелета при стационарном теле) даёт дрейф. Сброс при движении согласуется
   с догоняющим корнем.
2. **Система координат трекинга**: рассинхронизация кадров presentation /
   body yaw между XR-позами контроллеров и матрицей скелета.

Причина не установлена; обе гипотезы открыты.

## Новый диагностический канал ARM_BASIS

- `BFSoldierArmBasisDiagnostics` (.h/.cpp) — read-only наблюдение, никаких
  записей поз.
- Наблюдатель включается при `BFVR_DIAGNOSTICS=deep` в процессе клиента.
  Обычный лаунчер задаёт `off` по умолчанию. Для отладочного запуска у
  лаунчера есть опция `--diagnostics off|normal|deep`: она проверяет
  значение, при `normal`/`deep` сама включает обычный игровой запуск, а при
  недопустимом значении завершается с ошибкой.
- Сборка для проверки не должна заменять стабильную установку. Отдельный
  payload готовится скриптом `tools/Stage-BFVRPlayer.ps1` из
  `build/bfvr-win32-next` и `build/bfvr-x64-next`, после чего запускается
  elevated: `BFVR.exe --game-root "<путь к Battlefield 1942>" --diagnostics deep`.
  В подготовленной папке сохраняется пользовательский `UserConfig.txt`,
  чтобы повторить настройки теста.
- Проверено: `--dry-run --diagnostics deep` на подготовленном payload
  проходит, недопустимое значение отклоняется.
- Лимиты: не более 2 отчётов/сек, максимум 1200 отчётов за процесс
  (не менее ≈10 минут при предельной частоте); off/normal — без чтения
  матриц, таймера и записи отчётов.
- Отчёт `ARM_BASIS` фиксирует на кадр: generation контроллера, адрес солдата,
  yaw корня скелета, текущий yaw тела, yaw тела на момент публикации входа и
  их разницу, yaw корня в системе тела, origin корня и тела, запрошенные и
  решённые позиции правой/левой кисти, разницу `rightError` для правой и
  признак наличия решённой левой `leftValid`.
- Важно: targets/solved — кандидаты в пространстве нативного Skeleton;
  принадлежность root/world в отчёте диагностическая и не считается
  установленной.

## Как снять данные

Логи прошлого запуска пользователя показали diagnostics off — на них
опираться нельзя. Перед тестом:

1. Запустить подготовленный payload с `--diagnostics deep` (команда выше) и
   проверить свежие строки `ARM_BASIS`. Их отсутствие само по себе не
   доказывает выключенный режим: подходящий IK-проход также мог не
   выполняться.
2. Воспроизвести: стационарно, поворот стиком — затем ходьба (сброс дрейфа).

## Следующий шаг

Короткий стенд: стоя, поворот стиком (без ходьбы) против ходьбы, сравнить
`rightError`, разницу `leftSolved-leftTarget` при `leftValid=1` и yaw'ы
между фазами. Сессия короткая; при дискомфорте прекратить.
Лимит 1200 отчётов ограничивает объём данных, а не длительность теста.
