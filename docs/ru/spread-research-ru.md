# Spread / deviation в BF1942 — исследование (P2.11)

Статус: **исследование выполнено 13.11.2026**, read-only. Код игры и ассеты не
изменялись. Источник: отчёт фонового субагента + проверка кода BFVR.

## Где задаётся разброс

- Разброс — свойство оружия в `Objects/HandWeapons/<Weapon>/Objects.con` внутри
  `Mods\bf1942\Archives\Objects.rfa` (2788 записей в индексе).
  Пример: `Objects/HandWeapons/Bar1918/Objects.con`, блок
  `Rem *** Deviation Begin/End ***`.
- Свойства (MDT, значения в градусах):
  - `setFireDev x y z` — базовый разброс выстрела / +y за выстрел / −z за
    сервер-кадр (30 Гц);
  - `setDevMod st cr prone` — множители стойки (стоя/присед/лёжа);
  - `setMinDev` — минимум/стартовое значение;
  - `setTurnDev x y z w` — от поворота (pitch/yaw/спад);
  - `setSpeedDev x y z w` — от движения (вперёд-назад/стрейф/спад);
  - `setMiscDev x y z` — прыжок.
  Максимумы `x` всех свойств складываются.
- Фактические значения из `Objects.rfa` (примеры): K98/No4 `0 0 0`, min 0.25;
  M1/Type5 `1.8 0.3 0.08`, min 0.25; Mp40/Thompson/Mp18 `2.0 0.35 0.06`,
  min 0.4; BAR/DP/Sg44 `3.5 0.25 0.03`, min 0.75; Colt/P38 `2.5 1.5 0.07`,
  min 0.2. Bazooka/Panzershreck deviation не задают.
- Переопределение ассетов пофайловое: `Mods\XPack1\Archives\Objects.rfa`
  (464 записи) перекрывает базу (2788) по тем же путям; `init.con` задаёт
  порядок mod path, верхний путь выигрывает. Приоритет loose-файлов
  `Mods\bf1942\Objects\...` над `.rfa` **не подтверждён**.
- Сервер считает попадания сам (30 раз/с的位置 снарядов), `Network.con`:
  `ProjectileInfo → PMLinear`. `BF1942_w32ded.exe` содержит тот же
  `WeaponFire_Core` (file 0x106AB0).
- Runtime: `FUN_0053CDB0` (VA 0x53CDB0 = RVA 0x13CDB0) читает разброс как
  `float` по `weapon + 0x1A8`; при `> 0.01°` выбирает угол
  `uniform[-dev, +dev]` (LCG `this+0x274`) и доворачивает направление.
  BFVR уже хукает эту функцию в `src/client/WeaponAimOverlay.cpp`.

## Варианты

| Вариант | Сложность | MP-риск | Что меняется |
|---|---|---|---|
| Asset override (свой `Objects.rfa`) | средняя (нужен RFA-writer, отдельный mod/gameKey) | 0 на чужих серверах, но нельзя зайти на vanilla | в SP/LAN разброс заданный; в MP без эффекта |
| Runtime scale `weapon+0x1A8` в существующем хуке | низкая-средняя (offset есть, нужен гейт/restore/настройка) | 0, если сервер авторитетен; иначе возможное преимущество — не проверено | в SP/LAN пули идут точнее; в MP вероятно меняется только локальная предсказанная трасса |
| Не трогать | 0 | 0 | честный spread |

## Что уже сделано в BFVR

- В `WeaponAimOverlay.cpp` добавлен **экспериментальный, выключенный по
  умолчанию** режим: env `BFVR_EXPERIMENTAL_SPREAD_SCALE_PERCENT` (0..100).
  При значении <100 и только для accepted local infantry shot значение
  `*(float*)(weapon + 0x1A8)` умножается на масштаб, вызывается оригинальный
  `WeaponFire_Core`, затем значение восстанавливается. Есть проверки finite и
  диапазона 0..50°, счётчик `spreadPatched` в summary.
- Настройка в меню **не** добавлялась: режим только для локального замера.

## Протокол замера (следующий шаг)

1. SP-карта, оружие с известным deviation (например, Mp40: 2.0°).
2. Стена/мишень на 20 м, 10 выстрелов подряд с масштабом 100% и 0%.
3. Сравнить диаметр группы попаданий; ожидание: при 0% группа ≤ размера
   прицельной метки, без случайного конуса.
4. Затем 2 клиента на dedicated-сервере: смотреть hit-маркеры/попадания у
   второго игрока при масштабе 0% и 100%. Это ответит на вопрос, влияет ли
   клиентское значение на серверные хиты.

## Неизвестно / требует проверки

- Перекрывают ли loose-файлы `Mods\bf1942\Objects\...` запись в `.rfa`.
- Влияет ли клиентский `+0x1A8` на серверные хиты в MP (2 клиента).
- Стабилен ли `+0x1A8` в других сборках BF1942 (1.6/1.61/Origin) — нужен
  префикс-гейт (частично есть: проверка префикса `WeaponFire_Core`).
- Формула накопления `setFireDev → +0x1A8` (для плавного scale, не только 0).
- Нет ли mispredict при высоком ping.
