# Математические соглашения (наше)

Статус: актуально, подтверждено тестами.

## Конвенция D3D8

- `Matrix4` — row-vector convention: точка умножается справа (`v * M`).
- Трансляция находится в **строке 3** (`values[3][0..2]`), не в столбце.
- `TransformRowVector` применяет полный аффинный преобразование строкового вектора.
- Переход мир → локальные оси станции: **транспонирование** поворотного блока
  (ортогональная матрица: обратное = транспонированное).

## Конвенция `Yaw`

`Yaw(angle)` записывает:

- `values[0][2] = -sin(angle)`
- `values[2][0] =  sin(angle)`

Следствие: при yaw = π/2 локальная ось `+Z` станции отображается в мировом `-X`.
Это источник ранее «несовпадавших» тестов yaw: ожидания были пересчитаны под эту
конвенцию (`{10.000, 0.000, 4.550}` и `{10.200, 0.100, 4.800}`) и проходят.

## Допуски

- `IsRigidAffine`: 0.001 / 0.01.
- Тестовый допуск сравнения float: `0.0001F`.
- `kWorldUnitsPerMeter = 1.0F`.
- Клиппинг head offset к объёму станции: фактическое смещение фиксируется при
  превышении допуска `0.0001F` (counter `mountedHeadClamps`).

## Объёмы станции (pure-math константы)

Поскольку геометрии корпуса техники в runtime нет, объёмы — именованные
константы, не выдуманные per-class данные:

- `kTankStationVolume     = {0.45, 0.30, 0.60}`
- `kAircraftStationVolume = {0.30, 0.25, 0.55}`
- `kDefaultMountedStationVolume = kTankStationVolume`

`MountedStationClass { Unknown, Land, Air }`; `Unknown` → default envelope,
потому что запрос станции не даёт класс.
